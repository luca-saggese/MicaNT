### Dependency graph and implementation order

```text
M4/M6 lifecycle ──> M19 crash/debug ──> M20 SMP invariants ──> M26 time
       │                    │                 │                  │
       ├──> M23 PnP <───────┘                 ├──> M24 memory    └──> M21 suspend/resume
       │       │                              │
M14 flush/recovery ──────────────────────────┼──> M21 power-off/reboot
       │       └──> M22 IOMMU/DMA <───────────┘
       └────────────────────> M24 paging/cache
M19 + M20 + M22 + mature Mm/Io ──> M25 hardening and M27 virtualization (later)
```

Incremental path: (1) finish M4/M6 lifecycle and M14 storage flush/recovery basics; in parallel build M19 preallocated crash capture and M20 lock/IRQL audit, then AP execution and TLB shootdown; (2) deliver M23 static PCI/ACPI PnP and M22 DMA lifetime safety before enabling hardware remapping; (3) add M21 shutdown/reboot before suspend, and M24 file-cache reclamation before pagefile; (4) harden CPU/page protections in M25 and add M26 high-resolution timers as the per-CPU timer substrate stabilizes; (5) consider M27 only after all listed prerequisites. This is a dependency path, not a requirement to complete every milestone before unrelated Ring 3 work.
